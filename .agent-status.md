## AU-19 part 3: Web MIDI — COMMITTED (this round)
- src/midi_web.rs: the wasm32 `platform` for midi_io, the
  backend/web.rs JS-shim style (import module "vieww_midi", no
  wasm-bindgen): 8 imports (clock/count/string/open/close ×2/out_send),
  1 export `vieww_midi_receive` (bytes the shim copied into the input's
  scratch → Feed: parse, timestamp against the shim's
  performance.now() clock, queue; returns 0 when the input is gone so
  the shim detaches). Outputs are handle numbers from a Cell counter,
  closed in Drop. Inputs are thread-local registry slots with a 4 KiB
  scratch (chunked delivery; the parser reassembles).
- midi_io.rs: the bridge's PURE half compiled (and unit-tested) on
  every platform, the seq_encode/walk_packet_list pattern:
  `shim_string` (full-length-then-retry string protocol, lossy UTF-8)
  and `shim_check` (0 ok; −1 no access; −2 no such port; −3 the browser
  refused → Unsupported/NotFound/PermissionDenied; unknown codes said
  as unknown). 3 new always-run tests.
- web/vieww-midi.js: the shim — attach() starts
  requestMIDIAccess({sysex:true}) (the model carries SysEx; {sysex:
  false} skips Chrome's prompt and loses it), staged-honest contract
  (empty lists until it resolves; `ready()`; `onMidiState`), fresh port
  maps on every call (hot-plug), per-handle `onmidimessage` → scratch →
  receive, chunked at scratchLen, output send copies bytes out of wasm
  memory (never keeps a view — growth detaches), SecurityError → −3.
- web/test-midi.mjs: Node test against a simulated Web MIDI (fake
  access/ports/wasm memory + receive recorder): before/after grant,

  SecurityError −3 + close, hot-plug, clock advances, no-Web-MIDI page
  (fresh module via ?noapi import) → ready() rejects + −1, sysex:false
