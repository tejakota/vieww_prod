### WR-01 | P0 | Linux sandbox: `$HOME` is readable through PATH parents — "home secrets are invisible" is false on dev machines

**What it is.** `tools/src/sandbox.rs:241-276` (`read_only_roots`): for every `PATH` entry, the code pushes **the parent directory** as a read-only Landlock root:

```rust
for d in path.split(':').filter(|d| d.starts_with('/')) {
    let d = PathBuf::from(d);
    if let Some(parent) = d.parent() {
        if parent != Path::new("/") { dirs.push(parent.to_path_buf()); }
    }
    dirs.push(d);
}
if let Ok(home) = std::env::var("HOME") {
    dirs.push(PathBuf::from(&home).join(".rustup"));
}
```

On any machine with rustup (the default install puts `~/.cargo/bin` on PATH — this repo's own `AGENTS.md` workflow assumes it), the parent of `~/.cargo/bin` is `~`, so **the entire home directory becomes a read-only root**: `~/.ssh/id_rsa`, `~/.gnupg`, `~/.aws/credentials`, `~/.netrc`, browser profiles — all readable by any code executed through `shell`/`run-tests`/`git`, which is exactly where model-generated code runs. The module's own header claims the opposite (`sandbox.rs:10-11`).

The shipped test `home_secrets_are_invisible` (`sandbox.rs:560-571`) passes only because the fake home is planted under `std::env::temp_dir()`, not under `$HOME` — the test never exercises the PATH-parent rule.

**What it blocks.** The whole trust story: (a) the documented invariant is falsifiable; (b) the Rule of Two's "PrivateData" leg is a *fiction* — the split Fetcher/Mailer pattern is considered safe *because* the sandbox supposedly prevents a run-tests command from reading the person's data; with `~` readable, a 2-leg agent can exfiltrate `~/.ssh` contents into an artifact (test stdout is returned verbatim to the model, `sandbox.rs` `RunOutput::report`), and a downstream 2-leg Mailer ships it — no ask, by design. (c) Prompt-injection: untrusted web content can instruct generated code to `cat ~/.aws/credentials` into test output.

**How the leaders solve it.** Claude Code's bash sandbox uses OS-level sandboxing (Seatbelt on macOS, Bubblewrap on Linux) with explicit writable roots and no implicit home read grants (https://docs.anthropic.com/en/docs/claude-code/settings — "Bash sandbox", "Sandbox environments"). Devin gives each session a fresh throwaway VM (https://docs.devin.ai/) — the home is empty by construction. Cursor agent sandboxing defaults to a sandboxed workspace with the network and filesystem edges controlled (https://docs.cursor.com/agent/sandboxing).

**The fix.** Never push PATH parents. Resolve each PATH entry to the toolchain dirs actually needed:
```rust
// tools/src/sandbox.rs — replace the parent-push block
for d in path.split(':').filter(|d| d.starts_with('/')) {
    dirs.push(PathBuf::from(d));                 // the bin dir itself, ro+exec
    for sub in [".rustup", ".cargo"] {           // toolchains, not the home
        let cand = PathBuf::from(d).join(sub);
        if cand.is_dir() { dirs.push(cand); }
    }
}
```
Plus: explicitly do *not* add `$HOME`; add a regression test that plants a fake `~/.ssh` under a temp `$HOME`-substituted PATH and asserts refusal (today's test must move under `$HOME`-like conditions, e.g. by setting `HOME` and PATH to the temp tree in the test). Add `~/.cargo/registry` ro instead of the whole home if offline cargo is needed.

**Tests.** GitHub CI (ubuntu kernel 5.13+ Landlock): new test `home_paths_are_not_roots` planting `id_rsa` under `$HOME` with `~/.cargo/bin` on PATH, asserting the read is denied; self-hosted Linux (kabylake box runs 5.x — verify Landlock ABI≥1): same test + a fixture that runs `run-tests` with a command reading `~/.gnupg`; device farm: negative assertion on any host where a rustup default layout exists.

**Status: [OPEN]** (both branches).

### WR-02 | P0 | Sandbox depth: no syscall filter (seccomp), no PID namespace; networked commands share host process space

**What it is.** `tools/src/sandbox.rs:373-431` (`pre_exec`): the child does `setpgid`, rlimits, `unshare(CLONE_NEWUSER|CLONE_NEWNET)` **only when network is denied** (`if !allow_network && unshare(...) != 0 && handled_net == 0`), `prctl(NO_NEW_PRIVS)`, then Landlock rules. There is no seccomp-BPF filter, and no `CLONE_NEWPID` in any path. When `allow_network=true` (any agent holding the network permission — e.g. a worker, or a card with `network=true`), the command runs in the *original* user/PID namespace: it can see every process on the host and signal same-uid processes (the wright process itself, the daemon, the UI), `ptrace` subject to Yama (default `ptrace_scope=1` limits to descendants, but that is a sysctl, not a guarantee), and issue any syscall Landlock doesn't care about (`keyctl`, `mlock` DoS, `perf_event_open` on some configs, `unshare` again to escape the pgid discipline, etc.).

**What it blocks.** "Sandbox" is a filesystem+TCP wall, not a compute wall. A malicious generated binary (run-tests executes model-authored code) can DoS the harness (`kill(getpid_of_wright)`), interfere with parallel firings, or sit on host resources. `no_new_privs` prevents privilege escalation, which is why this is P0-not-catastrophic, but the claim "locks itself down with the kernel's own tools" oversells: Landlock's own docs position it as *path* access control, complementary to seccomp.

**How the leaders solve it.** Claude Code's sandboxing layer runs bash in OS sandbox profiles; Devin/Jules use whole VMs (https://docs.devin.ai/, https://jules.google/docs — Jules executes each task in an isolated cloud VM); bolt.new runs everything in WebContainers inside the browser sandbox — process isolation by construction (https://webcontainers.io). Cursor's agent sandboxing similarly sandboxes the workspace with network/filesystem edges (https://docs.cursor.com/agent/sandboxing). VS Code's extension host, and every CI runner, layer seccomp+namespaces under the app.

**The fix.** Add a seccomp filter and a PID namespace to `pre_exec` (the file is already an allowed-unsafe zone with SAFETY comments):
```rust
// sandbox.rs linux::run — inside pre_exec, after no_new_privs
unsafe { kill_scope(); }
let _ = unshare(CLONE_NEWPID);           // fresh PID ns; first child reaps
install_seccomp(ALLOWLIST);              // ~70 syscalls: read/write/…
```
Keep a small explicit allowlist (openat/read/write/close/execve/fork/clone/mmap/…), `ENOSYS` everything else; add `CLONE_NEWPID` unconditionally (cheap, removes host process visibility); keep `--die-with-parent` semantics via the pgid kill for stragglers (already present, `sandbox.rs:487`).

**Tests.** Self-hosted Linux: escape-suite (below, §7) — attempt `kill` of a decoy same-uid process, `ptrace`, `keyctl`, `perf_event_open`, `unshare` re-entry; each must fail or be killed. GitHub CI: a reduced suite on 5.13+ runners. Device farm: run the suite wherever Landlock exists; log ABI per host.

### WR-04 | P0 | Release channel: unsigned installers, no notarization, no auto-update

**What it is.** `wright-release.yml` builds Wright-Setup `.exe` (Inno Setup), macOS universal `.dmg`, Linux `.deb`, publishes with `SHA256SUMS.txt` (`wright-release.yml:214-217`). But: Windows binary is unsigned (`packaging/windows/wright.iss` — no sign step; RELEASE-NOTES.md:37 admits "unsigned (…SmartScreen). **What it blocks.** Real-world distribution. SmartScreen warnings + un-notarized Gatekeeper prompts are the #1 trust killer for a product whose tagline is *trust*. An attacker who can MITM the download (plain HTTPS helps, but a compromised mirror/CDN is the classic case) ships a malicious binary; SHA256SUMS only helps people who check, and is posted on the same channel it verifies. No updates ⇒ known-vulnerable versions live forever — the OpenClaw CVE story wright itself cites (ARCHITECTURE.md §6.7) is the counterexample.

**How the leaders solve it.** Cursor ships signed+auto-updating binaries (Squirrel; updates signed); Claude Code is npm-distributed with integrity via npm + Anthropic's signing on the API side; bolt.new/v0/Lovable are *web* products — the update problem is solved by not having binaries; Devin is a cloud service. Desktop leaders (VS Code, Slack) all ship signed auto-updates (update manifests + OS-level verification: Authenticode/Developer-ID+notarization).

**The fix.** wright already owns every needed primitive: an audited ed25519 (RFC vectors + OpenSSL cross-vectors), a signing-key provenance story (`runtime/src/signing.rs`), and recipes already refuse unsigned installs. Ship it end-to-end:
1. CI signing jobs: macOS Developer ID + `notarytool` (secret via `WRIGHT_SECRET_*`-style env, provenance recorded); Windows Authenticode (EV or Azure Trusted Signing) — key in GitHub secret, never in the repo.
2. An update *manifest* per channel: `wright-v<version>.manifest.json` = `{version, notes, assets:[{name, sha256, ed25519_sig}]}` signed with the release key; the app gains `wright update check` + a settings toggle (default on, phoning-home opt-in is the *only* new outbound traffic — keep it a plain GET of one static file, documented).
3. Verify-then-apply: download, check sha256 + ed25519 against the pinned release key compiled into the binary, then swap via atomic rename + restart prompt. Code sketch (uses existing modules):
```rust
// new: runtime/src/update.rs
pub fn verify_manifest(bytes: &[u8], release_pk_hex: &str) -> Result<Manifest, String> {
    let v = json::parse(std::str::from_utf8(bytes)?)?;
    let sig = from_hex(v.str_of("ed25519_sig").ok_or("unsigned manifest")?)?;
    if !SigningKey::verify(release_pk_hex, &canonical_bytes_without_sig(&v), &sig) {
        return Err("manifest signature failed".into());
    }
    Ok(Manifest::from_value(v))
}
```
4. Make `wright-release.yml` *fail* (not warn) if signing secrets are absent when `publish=true`.

**Tests.** GitHub CI: a job that builds a fake manifest + tampered asset and asserts `wright update check` refuses (unit-testable with `WRIGHT_EPHEMERAL_SIGNING=1`); self-hosted Linux + Windows: end-to-end update-apply on the real machines (the two boxes are perfect for channel dogfooding); device farm: N/A.

### WR-07 | P1 | HTTP tools: DNS-rebinding TOCTOU between the SSRF check and the connection

**What it is.** `tools/src/lib.rs:506-544` (`check_public`) resolves `host` and rejects private/loopback/link-local/CGNAT/metadata ranges. ## 5. Where wright already leads (code-backed)

1. **Offline-verifiable, signed provenance of agent work.** No competitor produces anything like `wright verify`'s six checks. Cursor/Claude Code/Devin give you a transcript you must trust; v0/bolt give you code with no attestation. wright: receipt over exact bytes, event-log hash, artifact + input hashes, blueprint commit, per-task `did:key` identities with delegation and call-digest attestations — checkable by a third party with no account, no model, no wright (`engine/src/verify.rs:1-37`). The identity layer (`runtime/src/identity.rs`) — "which agent did what, was it in scope, was the key dead after" — is beyond every harness on the market.
2. **Structural prompt-injection defense (the Rule of Two) as a compile-time gate.** The taint fixpoint (`rule_of_two.rs`) means a plan *cannot exist* with an unapproved 3-leg agent; the gate re-asks on every outbound step as belt-and-braces. Competitors enforce nothing structurally: Claude Code has permission *prompts*, Cursor has confirmations, Copilot Workspace frames but doesn't refuse. (Wright's remaining miss is WR-08 — the model isn't told what the taint system knows.)
3. **Deterministic blueprint IR + incremental refire economics.** Canonical serialization ⇒ formatting-independent hash ⇒ git-like versioning, structural diffs, and a task cache whose keys include permissions as provenance (`cache.rs`, ADR "permissions are provenance"). The measured counterexample is dsh's ~20M tokens/run with second-run == first-run cost; wright's second run is a cache hit (pinned by diff tests). No leader has diff-driven refire — they re-run conversations.
4. **Cost transparency as a first-class, enforced budget.** Pre-run estimate, per-firing AND daily caps, conservative-fail pricing, per-agent/model/tool attribution from provider usage (not the model's self-report), CSV for finance (`spend.rs`). Leaders: none show pre-run cost; Devin/Replit are post-hoc; v0 credits are opaque.
5. **Local-first with in-process models.** Qwen3-1.7B + Whisper run in-process, cross-checked token-for-token against llama.cpp/whisper.cpp in CI — zero external crates in the headless binary, one dependency (vieww) in the UI. No accounts, no telemetry (verified). vs. every named leader which is cloud-first or phone-home.
6. **Human-in-the-loop as typed policy, not vibes.** Confirm Gate summaries generated by code (never a model) with per-line provenance; approvals answerable from any terminal via files (`approve.rs`); unattended go-ahead bound to the blueprint hash and gated on ≥1 passing run with "time to trust" measured (`unattended.rs`). Claude Code's permission modes are the nearest analog and are not plan-bound.
7. **MCP done as adversarial protocol.** Hash-pinned servers (single-binary BLAKE3 or frozen trees `tree-blake3`), allow-listed tools, fresh process per call, answers marked untrusted — vs. the ecosystem's default trust-on-install (the OpenClaw CVE story). `wright mcp-hash` makes pinning a command, not a chore.
8. **The honest `browser` refusal.** Refusing loudly instead of shipping a half-sandboxed browser is a trust posture no competitor shares (they ship the browser and accept the risk silently).

## 6. Novel methodologies NO leader has today (PoC candidates)

### 6.1 Signed agent transcripts: the full provenance chain, verifiable offline
**What:** ed25519 already signs receipts and delegates identities. Close the loop into one verifiable artifact: `prompt → blueprint diff → every tool input/output hash → compiled/exported artifact`, all under the machine key, chained via the existing BLAKE3 call-chain in `identity.rs`. A third party (auditor, client, another *machine*) can replay the whole causal story offline.
**Why no leader has it:** none of them have (a) a typed IR whose hash is the commit, (b) per-task cryptographic identities, or (c) an in-house audited ed25519 with a documented key-provenance story. Cursor/Claude Code transcripts are append-only *text*; v0/bolt have no transcript at all.
**Feasibility (code-level):** every ingredient exists — `identity.rs` chains calls; `firing.rs` already records input hashes (`input_blake3` in `agent.rs:544`); `verify.rs` already re-hashes. The work is additive: extend the receipt with the per-task chain (a `transcript` array), extend `verify` with check #7.
**PoC sketch:** `receipt.transcript = [{agent, did, delegation, calls, calls_digest, attestation}, …]` (fields already serialized by `Closed::to_value`) + `verify.rs` check that recomputes each `calls_digest` from `events.jsonl` entries where `identity == did`. Proves: "the log's actions were made by identities the machine issued, within scope" — machine-checkable, no trust in wright-the-vendor.
**Tests:** extend `engine/tests/trust.rs` (already runs everywhere) with a tampered-identity case.

### 6.2 Deterministic blueprints as merge-base: multi-agent collaboration without a server
**What:** use `canon` + `diff` (already implemented and test-pinned) as the merge base for *concurrent* blueprint edits: two people (or two agents, or two machines) edit a blueprint; wright computes the structural diff against the common commit and refires only the affected subgraph per side — a git-style CRDT over a typed IR, no server, conflict = two refire sets unioned at the *task* level (tasks are idempotent under the cache because the cache key includes permissions and inputs).
**Why no leader has it:** their unit of work is a session (a conversation), not a versioned typed document; sessions don't merge. dsh explicitly lacks "a versioned project definition"; Copilot Workspace branches prose.
**Feasibility:** `diff.rs` already computes affected subgraphs; `cache.rs` makes re-running the union cheap; the store is content-addressed. The missing piece is a `wright merge <a> <b>` that produces the union graph and *reports* both refire sets honestly (it cannot promise to reconcile contradicting `intent` — that's a Confirm Gate question; the PoC should surface it, not hide it).
**PoC sketch:** `wright fork` (WR-12) + `wright merge` printing "A refires X+downstream; B refires Y+downstream; union = Z; conflicts: intent.summary (A vs B) — the Confirm Gate asks". Proves: collaboration without a server and without re-running the world.
**Tests:** GitHub CI mock-provider: two edits derived from one commit, assert cache hits for the untouched subgraph and the union receipt verifying.

### 6.3 Compile-gated codegen as a product promise: nothing shown until it compiles AND renders
**What:** the compiler already orders delivery after Testwright + Reviewer. Extend the *definition of done* to rendering: for `react`/`web` exports, gate the "Result" screen on (a) the package builds (export kind `Web`), and (b) the deterministic vieww renderer (or headless Chrome) produces screenshots that pass golden comparison — using the same metrics machinery as `film_lab/renders/*` (sheet.png + metrics.txt per shot, a pattern this repo already runs at scale).
**Why no leader has it:** v0/bolt verify nothing automatically (the human is the verifier); Cursor/Claude Code show diffs, not rendered truth; Devin's "playwright" verification is a bolt-on in the VM. None of them have a *deterministic in-house renderer* to pin goldens against — vieww's CPU rasterizer-as-oracle discipline (README root: "CPU rasterizer is default+oracle") is exactly the required primitive, and nobody else owns their renderer down to the pixels.
**Feasibility:** `wrightsite/examples/render.rs` already renders a vieww tree to PNG at three widths on the host; `wright ui --snapshot` renders 18 screens; `export.rs` can emit web builds. The PoC: an exported `react` skeleton served on loopback (WR-11 level 2), captured with the film-lab metrics, compared to a golden committed in `examples/`.
**Proves:** "the agent's output was *observed*, not assumed" — the phrase no AI builder can currently say.

### 6.4 Sandbox escape testing as a continuous product feature (device-farm fuzzing)
**What:** leaders sandbox by *policy* (permissions, prompts); wright sandboxes by *kernel enforcement* (Landlock/netns/bwrap). Enforcement can be *continuously tested*: a standing escape suite (WR-02 list + WR-01 regression + symlink/TOCTOU + DNS rebinding + scratch perms) run on both self-hosted machines and any device-farm host, with results recorded as receipts — the farm becomes a trust oracle, not just a perf lab.
**Why no leader has it:** their boundaries are in *their* code (prompt handlers), which they test as unit tests; kernel boundaries need real machines — none of them ship a product that runs on *your* kernel, so the question doesn't arise. wright's model (runs on the user's OS) makes it mandatory and uniquely possible.
**Feasibility:** the suite is plain `#[test]`s with `Policy` fixtures; the receipts system already records everything needed. PoC: `wright doctor --escape-suite` printing per-check verdicts, machine-readable.
**Proves:** "the sandbox holds on *this* machine, today" — per-host attestation, which is §6.1's transcript idea applied to the host itself.

### 6.5 Local-model-first agent with a model-agnostic tool schema
**What:** wright's `ToolDef` JSON schema + provider-agnostic `CompletionRequest` means the same blueprint runs on Qwen3-1.7B in-process, any OpenAI-compatible endpoint, or Anthropic — with the *gate* (not the model) enforcing tool validity. Add a "model quality report" per tier (bench.rs already exists): before an unattended go-ahead, wright can *measure* whether the local model passes the project's own tests, and refuse the go-ahead if not — model capability becomes a checkable fact, not a vendor claim.
**Why no leader has it:** they are cloud-model-first by business model; "run it locally, prove it locally" contradicts their revenue. For wright it's the default (no key needed).
**Feasibility:** `bench.rs` + `unattended.rs`'s "≥1 passing run" rule compose directly; the PoC is a config flag `unattended requires local-verified` that runs the last firing on the built-in model before the go-ahead is recorded.
**Proves:** "unattended" means *the machine* verified the plan works on *the model that will run it* — no leader can even express this sentence.
